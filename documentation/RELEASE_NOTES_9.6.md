# QSSTV 9.6.0 – MMSSTV template import and automatic configuration upgrades

**Status: integrated in the 9.6.0 development build; not officially released.**

MMSSTV single-template and batch import are included in this build. The program identifies itself as QSSTV 9.6.0. Linux settings use `~/.config/qsstv_9.6.0.conf` (or `XDG_CONFIG_HOME`), with automatic upgrade from older configurations. KG-STV is included as an experimental native mode; original-application interoperability and real-device validation remain open.

KG-STV has its own **KG-STV (experimental)** tabs alongside SSTV and HAMDRM. The native path uses QSSTV's selected audio devices and shared transmission/PTT lifecycle. It must not yet be described as compatible with the original KG-STV application.

## KG-STV live integration (experimental)

The source implements these experimental paths:

- Receive and transmit 320x240 images using the native MSK or 4L-FSK components, with optional payload error correction.
- Display partial images and the number of received blocks. **B** counts blocks; it is not a signal-to-noise measurement.
- Send standalone text without a TX image selected, using **Send Text**. The current conservative limit is 1..200 ASCII bytes; unsupported input is rejected without replacement or truncation.
- Show received messages and local send/cancel status as timestamped plain text. Local completion does not claim remote delivery.
- Send missing-block requests after a receive pass, and manually send requested blocks from the last completed cached TX image. Duplicate requests are bounded and deduplicated; changing the displayed TX picture does not replace that cache.
- Serialize image, text and BSR jobs through the same audio/PTT path. Stop, mode changes, playback failure and canceled preparation invalidate the appropriate job; stale completion messages cannot stop a subsequent transmission.
- Apply the existing RX/TX clock calibration. Synthetic controller tests include both modulation paths at +/-0.1% calibrated clock offsets.

Complete RX images can be saved automatically; partial images can be saved manually. KG-STV PNGs use the configured digital RX/TX image directories with a `KGSTV_` prefix. The RX preference **Save complete KG-STV images automatically** mirrors the existing RX auto-save preference. KG-STV does not enable the automatic repeater or FTP upload paths.

All current signal evidence is generated by this implementation. Original transmit filtering, numerical image fidelity, packet/session sequencing, non-ASCII text, noise/frequency/clock tracking and physical audio/CAT/PTT still require validation. Only one cached transmit image and one receive image are maintained; BSR replies are manual because sender/image association has not been validated against the original protocol. No release date is assigned.

## MMSSTV template import (integrated)

Import MMSSTV `.mtm` templates into QSSTV's native template editor and save them as `.templ` files for reuse as TX overlays. Supported objects remain editable, and supported dynamic fields map to QSSTV macros. A conversion preview reports missing fonts/resources and conversion limitations.

The editor now provides **File → Import MMSSTV template...** with a conversion preview and warnings before replacing the current canvas. Text gradients and simple contours are converted to editable native properties; embedded bitmap text fills are preserved as tiled textures. Ellipses are imported as editable native shapes; rounded frames are retained as embedded images. Rounded, elliptical and polygon masks on embedded pictures are preserved as image transparency. Common MMSSTV UTC/local date and time macros, compact time formats and lowercase contact callsigns are preserved through explicit mapping. Rapport-prefix and contest-suffix macros use the TX RSV field without inventing a default report. Whole-template sampled transparency is preserved, including overlapping objects, with a checkerboard import preview. **Edit → Template transparency...** allows changing the background and sampling point (including direct selection by clicking the preview), or disabling this behavior. The original `.mtm` stays untouched; save the converted result as `.templ`. Supported objects and known limitations are listed in the [import documentation](../docs/development/mmsstv-template-import-9.6.md).

Compatibility checks passed for all five example templates supplied with MMSSTV 1.13a FULL. They match the previously tested reference templates; custom templates remain subject to the documented conversion limitations.

The template editor also supports **File → Batch import MMSSTV templates...**. Multiple inputs are converted independently into a chosen directory, with collision suffixes, no replacement of existing files, and a per-file warning/error report. The open canvas is preserved.

Templates saved with sampled color-key transparency require the new template reader (`9.6` format). Older templates remain readable; ordinary templates without this metadata retain the legacy format. Template-format versions are independent of the application version used in configuration filenames.

## Versioned Linux configuration and automatic upgrades (integrated)

QSSTV now includes the complete running application version in the configuration filename. Version 9.6.0 uses `~/.config/qsstv_9.6.0.conf`; a future 9.6.1 build will use `~/.config/qsstv_9.6.1.conf` automatically. Files are stored directly in the configuration directory, without an `ON4QZ/` subdirectory. When `XDG_CONFIG_HOME` is set, that directory replaces `~/.config`.

The automatic upgrader runs before settings are read:

- If the current version's file already exists, QSSTV uses it without overwriting or merging it.
- Otherwise, QSSTV selects the numerically latest eligible predecessor from the configuration directory and the historical `ON4QZ/` location. At equal versions, the direct file takes precedence. Existing `qsstv_9.0.conf` files in either location are supported, as are configuration files from subsequent application versions.
- The complete source is copied unchanged, including unknown settings and Qt-encoded values. The original remains available for rollback. No manual copying is needed.
- Configuration files belonging to newer application versions are ignored; starting an older build does not downgrade or overwrite them.
- If no eligible configuration exists, QSSTV creates a fresh file for the running version and uses its default settings.
- A malformed or unreadable selected configuration, or a failure to create the new file, produces an explicit startup error instead of silently resetting settings.

New configuration files are readable and writable only by their owner. Upgrade operations are coordinated between simultaneous startup processes so that they do not overwrite each other's migration result.

Windows and macOS retain their existing native settings storage. Template-format versions remain independent of configuration filenames. See [configuration paths, migration and validation](PACKAGING.md) for details.

## Current status

Protocol investigation has identified framing, coding sequences, image-codec tables and packet types. Experimental native components now encode/decode packet frames and image blocks, generate/receive synthetic PCM and manage missing-block requests and repairs. A separate offline tool also produces image, standalone ASCII text and BSR WAV fixtures without opening devices or operating CAT/PTT. Device-free controller and real-widget tests cover the new live routing code; physical devices have not been tested. [Component and offline tests](../tests/kgstv-tests.md) describe coverage and remaining work. Compatibility with the original KG-STV application has not been established.

KG-STV is selectable as an **experimental mode** in this development build. Original-application compatibility, multi-sender/session behavior and operation on real audio/radio hardware remain unverified. These limitations are separate from the already tested MMSSTV import and configuration-upgrade features.

## Availability criteria

Release-grade compatible KG-STV support requires tests against original KG-STV signals, validation of the supported RX/TX paths, and regression checks for existing analog SSTV and HAMDRM modes. Any remaining restrictions will be documented with the release.

See the [KG-STV implementation and validation plan](../docs/development/kgstv-9.6.md) and [development roadmap](ROADMAP.md).


KG-STV reference check: an external 4L-FSK MP3 exposed and enabled correction of the original BGR color-channel convention in both native TX and RX. Offline decoding at 24 kHz recovers all 300 image blocks; the live 12 kHz controller now also recovers all 300 using an additional bandlimited fractional timing path. Original outbound/text/BSR compatibility and physical hardware validation remain pending.

A separate external 4L-FSK ASCII text recording also passes the production controller regression: exactly one unchanged message, without invented sender metadata. This validates reception of that sample, not original outbound, non-ASCII or BSR interoperability.

Windows distribution: build and release workflows now produce a single portable `QSSTV-9.6.0-Windows-x86_64-portable.exe`. It temporarily extracts the bundled application/Qt/runtime files, starts without installation and cleans them after normal exit. Existing per-user settings and persistent image directories are retained. The Windows CI launcher smoke test and real clean-machine/hardware validation must still be executed.
